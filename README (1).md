# ☕ 인마이험블 재고관리 시스템

카페 아르바이트를 하며 느낀 두 가지 불편에서 출발한 프로젝트입니다.
1. 레시피를 그때그때 확인하다 실수가 생기는 문제
2. 파트타이머마다 담당 재료가 다른데, 재고 파악이 늦어 발주 타이밍을 놓치는 문제

**담당 파트별로 재고를 체크**하고, **재료 소모 추이로 인기 메뉴를 추정**해 사장님의 발주 판단을 돕는 시스템입니다.

## 주요 기능

- **재고 체크 입력**: 파트타이머가 본인 담당 파트를 선택하면 담당 재료만 표시, 현재 수량 입력 시 자동 기록
- **재고 전체보기**: 파트별 필터로 전체 재료 현황 확인, 신규 재료 등록
- **레시피 관리**: 메뉴별 1잔당 재료 소모량 등록
- **발주 리포트(사장님용)**: 부족 재료와 추천 발주량 자동 계산, 재고 체크 기록(체크 시점 간 감소량)을 기반으로 최근 7일/30일간 인기 메뉴 추정
- **대시보드**: 파트별(공통·파트1·파트2·파트3) 재고 현황 시각화

## 담당 구조 (예시 데이터)

| 파트 | 담당자 | 메뉴 |
|---|---|---|
| 공통 | - | 아메리카노, 카페라떼, 바닐라라떼 |
| 파트1 | 새난 | 말차라떼, 초코라떼, 아인슈페너 |
| 파트2 | 동락 | 아이스티, 밀크티, 키위소르베 |
| 파트3 | 연지 | 레몬에이드, 히비스커스티, 알로에CCC |

## 기술 스택

- Python, Streamlit
- SQLite (별도 DB 서버 없이 단일 파일로 관리)
- Pandas (데이터 조회·표시)

## 실행 방법

```bash
pip install -r requirements.txt
streamlit run app.py
```

## 인기 메뉴 추정 방식 (참고)

실제 판매 기록이 아니라, 재고 체크 시점 사이의 재료 감소량을 기반으로 추정합니다.
여러 메뉴가 같은 재료(우유 등)를 공유하기 때문에 정확한 판매량은 아니며, 메뉴의 레시피 재료 중 가장 적게 늘어난(병목) 소모량을 기준으로 상대적 경향만 보여줍니다.

## 향후 개선 방향

- 레시피 데이터 구글 드라이브 연동
- 담당자 로그인/인증
- 발주 알림 자동화 (이메일/슬랙 연동)
